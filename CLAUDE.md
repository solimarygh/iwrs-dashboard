# CLAUDE.md — IWRS Invertebrate Welfare Science Dashboard

Context for Claude Code. Read this before changing anything in the repo.

## Who and why

- Maintainer: Solimary García Hernández (behavioral ecologist, postdoc at USP, São Paulo).
  Works in R. Prefers explanations in Spanish (or Portuguese); code, comments and the
  dashboard UI are in English.
- Built for the **Insect Welfare Research Society (IWRS)**, a US-based 501(c)3 society.
  The output feeds a "state of the field" report on insect/invertebrate welfare science.
- **Always check that classification choices are biologically coherent.** Solimary reviews
  outputs critically; flag uncertainty instead of guessing.

## What the dashboard must answer (IWRS brief, annual 2016–2026)

Priority order:
1. Number of peer-reviewed publications, broken out by sentience / emotion / affect /
   consciousness / welfare (pain/nociception reported separately).
2. Ratio of conceptual/theoretical/methodological/perspective papers to empirical papers
   (from a hand-coded sample, see Validation).
3. Distribution across animal welfare journals (Animal Welfare, Applied Animal Behaviour
   Science), entomology journals (Journal of Insect Physiology) and high-impact
   multidisciplinary journals (Nature, Science, PNAS).
4. Talks, symposia/workshops/panels at major conferences (ESA, ICE, Insects as Food and Feed),
   academic events, PhD/Master's theses, number and USD value of grants from non-EA funders,
   media mentions. These are NOT in OpenAlex: they are curated by hand in `data/manual/*.csv`
   (see `data/manual/README.md`).

Also wanted later (all-time): top 10 most cited papers, publications citing the IWRS research
guidelines, university policies, training courses, producer welfare codes, and IWRS's own
stats (membership by year/country incl. a world map of members, seminar attendance, YouTube
views, grants, husbandry protocols, website visits).

## Pipeline

```
config/query_config.yaml      single source of truth for the corpus definition
R/00_utils.R                  config loading, OpenAlex API, classification, relevance filter
R/01_fetch_openalex.R         -> data/raw/openalex_<date>.rds   (git-ignored)
R/02_build_records.R          -> dashboard/app/data/records.json + data/processed/*.csv
R/03_validation.R             -> recall (gold set), coding sheets, validation_summary.json
dashboard/app/                static site (HTML/CSS/vanilla JS + Chart.js), GitHub Pages
```

Run from the repo root, in order: `Rscript R/01_fetch_openalex.R`, then `02`, then `03`.
The OpenAlex API key lives in `~/.Renviron` as `OPENALEX_API_KEY`. **Never write the key into
any file in the repo.**

`data/processed/corpus_full.csv` (~60 MB, includes abstracts) is regenerated by `02` and is
git-ignored. Do not commit it.

## Corpus definition: decisions already made

- **Source:** OpenAlex only for now (WoS/Scopus/SciELO maybe later).
- **Years:** 2016–2026; 2026 is a partial year and is flagged everywhere.
- **Types:** article, review, book-chapter (review series such as *Advances in Insect
  Physiology* are indexed as chapters). Retracted works excluded.
- **Scope = IWRS mission:** insects plus terrestrial invertebrates (arachnids, myriapods,
  gastropods) and aquatic invertebrates (crustaceans, horseshoe crabs, cephalopods).
  - Horseshoe crabs are **chelicerates**, grouped with arachnids, not crustaceans.
  - Mites and ticks are **not** searched (literature dominated by parasitology).
  - Taxon groups are multi-label; "general" catches invertebrates/molluscs/bivalves or
    papers with no specific group.
- **Themes:** sentience, emotion, affect, consciousness, welfare, pain/nociception.
  - "affect" alone is never used (the verb matches everything); use affective,
    affect-like, valence, cognitive/judgement bias.
  - **Nociception is not evidence of sentience.** Papers whose only theme is
    pain/nociception are flagged `noci_only` and hidden by default in the dashboard.
- **Search syntax gotcha:** OpenAlex rejects wildcards inside quoted phrases in Boolean
  queries (HTTP 400). List singular and plural instead. `load_config()` checks this.

## Relevance filter (most important quality step)

Retrieval is deliberately broad (~18k works); most of it is noise. `relevance_reason()`
(rules in `query_config.yaml -> relevance`) keeps a paper only if:
1. it is not caught by `exclude` (homonyms: sport cricket, bee-colony/moth-flame
   algorithms, poetry/fiction; human contexts: stings, envenomation, dengue/malaria/Zika,
   food allergy, phobia; welfare of vertebrates fed with insects, e.g. "broiler welfare");
2. it is not a human-emotion paper (only emotion/affect/pain themes + people words);
3. the **title** has a taxon and a state term, or one **abstract sentence** has them within
   `window` (8) words.

First real run (2026-10-07): 18,222 retrieved → 1,518 relevant (1,218 without
nociception-only); 86 papers in 2016 → 182 in 2025.

Known risks to audit: exclusion patterns can drop real papers (e.g. "fish welfare and
crustacean welfare"); window may miss papers that describe welfare without nearby state words.

## Validation (pending — needs human coding)

- `data/validation/gold_set.csv`: currently only 2 placeholder DOIs. Needs 30–50 papers
  Solimary knows belong to the field. Recall is reported by `03`.
- `data/validation/coding_sheet.csv`: 200 relevant papers. Two coders mark `relevant` (y/n)
  and `study_type` (empirical / conceptual / review / methodological), saved as
  `coding_sheet_coder1.csv` and `coding_sheet_coder2.csv`. Gives precision, Cohen's kappa and
  the conceptual : empirical ratio (by period, 2016–2020 vs 2021–2026; too few for per-year).
- `data/validation/dropped_sample.csv`: 100 papers the filter dropped (50 by exclusions,
  50 other) to estimate false negatives.
- Tune the filter **before** the two-coder round so nobody codes twice.

## Dashboard

- Static, no build step. Loads `dashboard/app/data/records.json`; all filtering, charts and
  CSV export happen client-side.
- `scripts/make_demo_data.js` makes synthetic data (meta.demo = true shows a banner). Never
  ship demo data as real.
- Colour palette was validated for colour-vision deficiency (light and dark); the UI accent
  (moss green) is never used as a data series.
- Deployed by `.github/workflows/deploy-dashboard.yml` when `dashboard/app/**` changes.
  GitHub Pages is not switched on yet: wait until the numbers are validated.
- Design credit: inspired by the Canadian Metaresearch Dashboard
  (github.com/esantos2ua/metaResearchDataChallenge) and COKI.

## Working conventions

- Corpus changes go through `query_config.yaml`, not hard-coded in R.
- After changing search terms, re-run `01`; after changing classification/relevance rules,
  `02` is enough (it warns if the config changed since the snapshot).
- Before calling a number final, check it against a sample of titles.
- Commit messages in English; explain what changed in the corpus and why.
